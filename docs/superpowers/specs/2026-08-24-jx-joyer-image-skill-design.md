# JX Joyer Image Skill 设计

日期：2026-08-24

## 目标

创建一个可公开分享的 Codex Skill，以独立 Python CLI 直接调用京东 Oxygen 模型网关，复刻“京喜采销生图 / JX Joyer Image Studio”现有生图工作流。Skill 不依赖网站、JD Space、ERP、数据库、浏览器会话或网站后端。

目标用户在京东内网或 VPN 环境中，通过自己的 Oxygen Key 执行个性化生图任务。仓库公开发布，采用 MIT 许可证。

## 固定模型契约

- Base URL：`http://llm-gw.jd.local/v1`
- 文案接口：`POST /responses`
- 文案模型：`GPT-5.6-Sol-joybuilder`
- 无参考图：`POST /images/generations`
- 有参考图：`POST /images/edits`
- 生图模型：`GPT-image-2-joybuilder`
- Key：仅从运行时环境变量 `JD_LLM_API_KEY` 读取

不得把真实 Key 写入源码、配置文件、命令参数、测试、日志、任务清单、图片元数据或 Git 历史。

## 方案选择

采用“单一 CLI + 子命令 + Skill 路由”的实现。

未采用每种能力一个独立脚本，因为会复制鉴权、限流、重试、错误映射和文件处理逻辑。未采用通用 YAML 工作流引擎，因为首版复杂度和维护成本超过实际收益。

## 能力范围

### 商品套图

- 六种任务：主图、场景图、卖点图、白底图、认证图、四宫格图。
- 支持 `1:1` 和 `3:4`。
- 支持 `1K`、`2K` 和 `4K` 档位。
- Provider 尺寸映射：`1:1` 的 `1K/2K` 为 `1024x1024`，`4K` 为 `2880x2880`；`3:4` 的 `1K/2K` 为 `1152x1536`，`4K` 为 `2448x3264`。
- 最终 JPEG 归一化：`1:1` 为 `800x800`，`3:4` 为 `600x800`。
- 支持卖点、长标题和短标题生成；只补齐用户选择且为空的字段，不覆盖手工内容。
- 支持选定图片生成、失败项重试和基于原记录比例的派生修改。

### 商品详情页

- 创建本地项目并导入商品图片和商品事实。
- 生成或编辑详情页文案。
- 支持详情页模块的全量生成、单段生成、单段重试和派生修改。
- 保存分段修订版本，支持恢复历史版本。
- 导出详情页长图及任务清单。

### 自由工作台

- 无参考图文生图。
- 单张或多张参考图编辑。
- 支持固定比例、自定义比例和自适应比例。
- 支持批量任务、失败项重试、单图下载和批量下载。

### 批量修图

- 多张源图使用统一提示词处理。
- 支持公共参考图。
- 支持固定、自定义和自适应比例。
- 支持失败项重试，并保持首轮参数与参考图一致。
- 不实现已回滚的 fidelity-outpaint 像素锁定补边方案。

### 爆款复刻

- 导入模板图并生成结构分析。
- 生成或接收切片规划、补充问答和文案。
- 支持全部分片或单个分片生成。
- 结果按分片和修订版本保存。

### 通用能力

- 对已有结果执行追加提示词派生编辑。
- 保存本地任务历史、输入摘要、输出文件、状态、错误和重试次数。
- 支持任务列表、任务详情、取消标记、结果下载和清理。
- 生成 `manifest.json`，但不记录 Key、Authorization Header 或完整 Data URL。

## CLI 设计

统一入口为 `python scripts/jx_joyer.py <command> [options]`。

主要命令：

- `doctor`：检查 Python、依赖、网络可达性和 Key 是否存在；默认不消耗模型额度。
- `copy`：调用文案模型生成结构化文案。
- `generate`：自由文生图。
- `edit`：使用一张或多张参考图编辑。
- `ecommerce`：执行商品套图流程。
- `detail`：执行详情页项目与分段流程。
- `batch-edit`：执行批量修图。
- `replica`：执行爆款复刻流程。
- `derive`：对已有结果追加修改。
- `history`：查看本地任务历史和结果。

复杂任务使用 JSON 任务文件输入；常用简单参数支持命令行选项。CLI 输出结构化 JSON 摘要，便于 Codex 判断任务状态和继续重试。

## API 客户端

- 一个进程共享一个客户端实例。
- 文案并发最多 20。
- 图片并发最多 4，图片请求启动速率最多每秒 1 次。
- 默认超时 600 秒，最大尝试 4 次。
- 对网络错误、HTTP 408、409、425、429 和 5xx 重试。
- 429 优先遵循 `Retry-After`，无有效值时等待 60 秒。
- 文案兼容 `output_text` 与 `output[].content[].text`。
- 图片兼容 `data[0].b64_json` 与 `data[0].b64Json`。
- 不记录请求头或完整图片 Data URL。

## 本地数据模型

默认输出根目录由 `--output-dir` 指定；未指定时使用当前目录下的 `jx-joyer-output/`。每次运行创建独立任务目录：

```text
jx-joyer-output/<task-id>/
├── manifest.json
├── inputs/
├── outputs/
└── previews/
```

任务清单保存可复现的非敏感参数、提示词、尺寸、模型、输出路径、状态、耗时和错误分类。参考图可按用户选择复制到任务目录；默认只记录相对路径和内容哈希。

## Codex 使用方式

- 普通文生图使用 `generate`。
- 用户提供参考图时使用 `edit`，不得创建空白参考图模拟文生图。
- 电商整套素材使用 `ecommerce`。
- 详情页、批量修图或爆款复刻分别进入对应高阶流程。
- 信息不足时只询问会影响结果的关键参数；可安全推断的参数使用明确默认值。
- 任何会消耗真实额度的调用前展示预计请求数量，并取得用户明确确认。

## 安全边界

- 只允许从环境变量读取 Key；不提供持久化 Key 的命令。
- 不接受将 Key 写入任务 JSON、`.env`、命令参数或交互历史。
- 公开仓库不包含真实 Key、Cookie、ERP、生产数据或真实请求响应。
- 不创建公网代理，不让浏览器直接访问内部网关。
- 不依赖或访问 `ct.space.jd.com`、Space 项目 349、`/app/data` 或外部商家站资源。
- 不读取、上传或迁移现有网站用户数据。
- 输出文件仅写入用户明确选择的本地目录。

## 测试策略

- 使用 MockTransport 离线验证三个接口的 URL、模型、请求体和响应解析。
- 覆盖无参考图与有参考图分流。
- 覆盖限流、并发、超时、`Retry-After`、重试上限和错误脱敏。
- 覆盖六类商品图、尺寸映射、JPEG 归一化和手工文案优先。
- 覆盖详情页、工作台、批量修图、爆款复刻、派生修改和本地历史。
- 使用生成的无敏感测试图片，不提交真实商品图或生产响应。
- 运行 Skill `quick_validate.py`、Python 单元测试、CLI 模拟端到端测试和敏感信息扫描。
- 真实网关冒烟默认不执行；只有用户明确授权且 Key 通过安全运行时环境提供时才执行。

当前项目禁止 Codex 子代理，因此 Skill 行为验证使用本地自动化测试和人工场景检查，不使用子代理压力测试。

## 发布设计

- 在当前项目的已忽略目录 `output/jx-joyer-image-skill/` 中维护独立 Git 仓库，避免修改或混入 Space 网站仓库。
- 默认 GitHub 目标为公开仓库 `CTctikki/jx-joyer-image-skill`。
- 初始分支为 `main`，提交中仅包含 Skill 自身文件。
- 发布前确认父级 Space 仓库仍保持干净。
- 使用 GitHub CLI 创建公开仓库并推送；不修改 Space 网站远端、不推送 `upstream`、不部署 Space。

## 完成标准

1. 所有声明的工作流均有可执行 CLI 路径和离线测试。
2. Skill 能让 Codex 根据任务选择正确工作流。
3. 文生图与参考图编辑使用正确接口，不以空白图代替文生图。
4. 限流、重试、超时和错误映射保持一致。
5. 所有输出可追踪且不含凭据。
6. 父级 Space 仓库无改动。
7. 独立仓库通过验证并成功公开推送。
