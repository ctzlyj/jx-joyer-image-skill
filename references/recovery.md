# 工作台恢复与本地导出

## 读取真实状态

`history --task TASK_ID` 不需要 Key。工作台在每次图片调用前持久化 `running`，每张结束后立即保存成功/失败、实际像素；未开始的图片为 `pending`。使用 `created_at/updated_at` 和逐图状态汇报进度，不把 CLI 返回前的等待称为失败，也不虚报预计完成时间。

CLI 是本地同步执行，不是 Web 的 202 接口或持久后台队列。进程中断、终端失联或超时后，先回读清单；`running/pending` 的结果未确定，不能直接重放整个任务。确认是否仍有执行进程、已写出结果及上游回执后再决定恢复方式，不自动改为失败。

## 只重试失败图片

明确要求重试后执行 `workbench --retry TASK_ID [--asset image-2 ...] --yes`。没有 `--asset` 则只选失败项；没有失败项不调用模型。重试会产生新的模型请求，按用户已有授权执行，不要求重复确认相同授权。

- 成功图、已取消图、未知 ID 不可选作失败重试；需要另一版效果时使用派生或新任务。
- 新工作台任务复制参考图到自身 `inputs/`，保存原始提示词、提交尺寸与参考图 SHA-256；原素材随后改动不影响重试。
- 缺少/改动快照、旧版无快照任务不猜测重建；说明无法可靠重试，用户如需要，可按明确素材创建新任务。
- 原任务持有跨进程执行锁。同一任务并发重试立即拒绝，避免覆盖状态和重复生图；进程退出释放锁，但不自动将未知状态变成可重试状态。
- `image_requests` 是工作流发起的图片调用次数，包含主动重试，不等于网关内部尝试次数或计费账单。HTTP 错误另外提供 `attempts`；不能仅凭这些计数断言扣费结果。

## 导出和原图比较

`export --task TASK_ID [--asset ID ...]` 只读取成功的输出图片，在当前任务 `exports/` 新建 ZIP；不生成、不补画、不带输入素材、提示词或清单。失败/未知项、文件缺失或路径越界直接拒绝，不为导出自动重试模型。

独立 Skill 保留生成结果、派生任务的来源字段以及原始文件，助手可按用户要求对比展示；不需要复制网页版预览对话框。查看真实像素以文件或 `width/height` 为准，提交 `2K` 不代表模型一定返回 2048 像素。

## 合并和回退

保留用户输出、清单和本地增强，更新源码后离线运行测试及 `doctor`。旧历史可以继续查看和导出，只有具备新快照的工作台失败项支持新增重试能力。没有自动清理或迁移历史，不导入浏览器草稿/ERP 数据。回退只还原本次源码，不删除结果、不回滚任务文件、不自动重放请求。
